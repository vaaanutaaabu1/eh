Every new upload goes to the next database in turn (DB1 → DB2 → …) and a database is skipped once it reaches 95% of its storage or transfer limit. A document's original file and its page images stay together on one database. Stored here counts every file on that database, including page images. Files already uploaded keep working wherever they are. Limits come from SHARD_STORAGE_LIMIT_MB and SHARD_TRANSFER_LIMIT_MB.

Older files still inside the main database

Loading…

    
Moves one file at a time to DATABASE_URL2…N (never back onto DATABASE_URL1) and leaves a pointer in its place; nothing is removed before the pointer is saved. You can stop and start again at any time. Reading the old files uses the main database's monthly transfer once. Afterwards the main database stops growing from them, but Neon only gives the freed space back to new rows: the size shown for DATABASE_URL1 will not drop by itself. No backup runs while a move is running.

    
Check and clean up

    

    

    
Check reads only the ids, not the files. Remove unused files deletes files on DATABASE_URL1…N that no document, order or upload points to any more (older than a day). The site also does this by itself every day.

    
Get the original files out

    
On your computer (with backend/.env holding DATABASE_URL1…N): npm run export-files -- --out D:\my-files. It reads the files from every database and writes them in their original format, with an _index.csv that says which database each file came from. From a full backup: npm run export-files -- --from-backup <unzipped folder>/database --out D:\my-files. See NEON_GUIDE.md.
